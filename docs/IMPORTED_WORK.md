## Preservation and portability

Notebook/source copies and supplied attribution/licences are retained. Historical outputs and dataset/assets stay in the original repos; local asset copies are ignored by Git. Cache folders, IDE settings, Git metadata, notebook checkpoints and generated bytecode are excluded. Source files are unchanged unless the manifest records a portability or credential edit. No study dates, new results, course completions or supervisor approval have been generated.

When an absolute/home-relative dataset literal identified a unique source file, it was replaced by a relative path to that same asset. The data-export notebook uses the imported Pandas deliveries dataset, and the SQLite lesson uses its included `rideshare.db`. The OMDb lesson now reads `OMDB_API_KEY` from the environment and uses a request timeout; embedded key text is redacted from the imported notebook. The original repositories' historical commits are not rewritten.

## Environment

Use [Anaconda + uv + Jupyter Notebook](ENVIRONMENT.md). Core requirements include notebook/ipykernel, plotting, Excel, Plotly, HTTP and SQL connectors. `requirements-optional.txt` covers ydata-profiling, PyGWalker, AutoViz and OpenCV. A MySQL server, external APIs and their credentials are separate from Python-package installation.

Historical lessons may deliberately show failed calls (for example an incomplete `pd.read_json()` call), reference a local service, install optional packages or demonstrate file writes/removal. Inspect those cells and run the relevant lesson in a scratch folder. Preserved historical errors are not new import failures, and a complete rerun of every lesson is not claimed.
